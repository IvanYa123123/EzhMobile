# Тесты EzhMobile

Два независимых набора: Kotlin-тесты бэкенда (`:core:test`) и смоук
интерфейса на jsdom. Kotlin-тесты идут в CI вместе со сборкой APK
(`.github/workflows/build.yml`), jsdom — в отдельном workflow `Tests`
(`.github/workflows/tests.yml`).

## Зачем это

Тесты здесь **регрессионные**: каждый исправленный баг получает проверку,
которая падала бы до исправления. Так баг не возвращается незаметно — особенно
после правок в общем бандле `app.bundle.js`.

Правило простое: **новый баг → новая проверка в подходящий набор**. Не нужно
писать тест на каждую строчку; достаточно одной проверки на сломанный сценарий.
Дешёвые проверки (формат ответа, заголовки, наличие элемента) пишутся сразу;
дорогие сценарии (полный прогон UI) — только для того, что уже ломалось.

## Бэкенд: `./gradlew :core:test`

Тесты лежат в `EzhAndroid/core/src/test/kotlin/`. Ничего внешнего не нужно:
сеть СевГУ и Moodle подменяется фейками (`TestSupport.kt`), база — временный
SQLite через JDBC.

```bash
./gradlew :core:test
```

Что покрыто:

- **Планировщик** (`PlannerTest`): результат совпадает с golden-файлом,
  снятым с Python-версии (318 и 210 пар), и бюджет 22 с корректно выставляет
  `exhausted`.
- **БД** (`DatabaseTest`): CRUD всех репозиториев, уникальность slug,
  пересчёт прогресса лабораторных.
- **API** (`ApiTest`, `TeachersApiTest`, `MoodleApiTest`, `GroupsRoutesTest`,
  `StaticRoutesTest`): статусы и тела ответов, `Cache-Control` (включая
  `no-cache` для статики — иначе WebView показывает старый интерфейс после
  обновления APK), CSP, `X-Schedule-Exhausted` и пометка синка только при
  полной загрузке, бэкап туда-обратно, `.ics` (409 до загрузки, 200 после),
  rate-limit (429), группа из `Group.txt` и API, статика и защита от `..`.
- **Преподаватели**: разбор HTML (1008 человек, отсев «Вакансия УПП», «0 - ОМР»),
  разбор ICS (600 пар, сортировка, поля), кэш и офлайн-поведение.
- **Moodle**: логин/401/500, кэш статистики, warnings при нераспознанной
  вёрстке, 429 при параллельном обновлении, 499 при отмене.
- **Паритет с Python** (`GoldenContractTest`): 31 запрос из
  `tests/fixtures/golden/api_contract.json` (снят с Flask-версии до удаления
  бэкенда) прогоняется через Kotlin-сервер; сверяются статус, заголовки
  (`Content-Type`, `Cache-Control`, `X-Schedule-Exhausted`,
  `Content-Disposition`) и тело (JSON — структура, `.ics` — текст). Это ловит
  случайные изменения формата ответов, о которых не знает UI.

## Интерфейс: `tests/js/ui.test.mjs`

Страница целиком грузится в jsdom против заглушечного сервера
(`tests/js/stub-server.mjs`, Node): настоящая статика из `assets/static`,
фиктивные расписание/преподаватель/друзья.

```bash
node scripts/fetch_vendor_assets.mjs
cd tests/js
npm ci --no-audit --no-fund
node --test ui.test.mjs
```

Что покрыто (каждый пункт — ранее сломанный сценарий):

- страница поднимается без `ReferenceError` (из-за одного такого падала вся
  инициализация);
- группа восстанавливается из `localStorage`;
- 7 колонок календаря, смена недели после вкладки «День» и отсутствие стрелок
  в шапке расписания;
- на телефоне настройки открываются отдельной вкладкой (контент переезжает в
  `#settingsTabHost`, модалка не показывается), на десктопе — модалкой;
- при входе в настройки форма заполняется сохранёнными значениями, иначе любое
  изменение сбрасывало все переключатели и тему;
- стиль расписания: по умолчанию одна колонка (attr `data-schedule-cols="1"`),
  переключатель «Расписание в две колонки» включает две и сохраняется;
- если приложение закрыли на вкладке «День», после перезапуска она
  восстанавливается с уже отрисованным днём, а не пустая;
- свайп влево/вправо: на «Расписании» и «Людях» листает неделю, в «Дне» —
  по одному дню;
- «К текущему дню» возвращает сегодняшний день и во вкладке «День»;
- раскрытый список пар показывает стрелку вверх, пустой день — «Свободный день»
  без эмодзи;
- все модальные окна центрированы по вертикали;
- 5-я кнопка нижней панели открывает настройки;
- во вкладке «День» нет кнопок перехода к заметкам/событиям;
- у друга с «все подгруппы» это написано в заголовке;
- стрелок перестановки друга больше нет;
- статус-строка есть и во вкладке «День», точность «до сотых» убрана.

## Чего здесь нет

- Живых запросов к СевГУ и Moodle — они нестабильны и не должны ронять CI.
- Инструментальных тестов на реальном Android (эмулятор в CI не поднимается).
- Полного покрытия JavaScript: смоук проверяет только сценарии, которые уже
  ломались.

Фикстуры (`tests/fixtures/`) сняты с сайта один раз и лежат в репозитории:
`site/` — сырые ответы, `golden/api_contract.json` — эталонный контракт API
для сравнения при будущих изменениях.
